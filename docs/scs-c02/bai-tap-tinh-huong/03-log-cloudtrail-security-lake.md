### Câu 1 `hard`

External compliance auditors require cryptographic proof that AWS CloudTrail log files stored in an Amazon S3 archive bucket over the past 12 months have not been modified, deleted, or tampered with after AWS delivered them. CloudTrail Log File Validation was enabled when the trail was created. How should the security engineer verify the integrity of the log files?

- **A.** Compare the S3 ETag of each CloudTrail log file against the MD5 checksum stored in AWS CloudTrail Lake.
- **B.** Run `aws cloudtrail validate-logs` to verify the hourly digest RSA signatures and the SHA-256 hashes of every log file.
- **C.** Enable S3 Server Access Logging on the CloudTrail bucket and query it with Amazon Athena to verify no PutObject calls occurred.
- **D.** Decrypt the CloudTrail log files using the AWS KMS public key to verify that the files were generated by AWS.

<details><summary>Xem đáp án, Dịch nghĩa & Giải thích chi tiết</summary>

> **Ý nghĩa câu hỏi:** Kiểm toán viên tuân thủ bên ngoài yêu cầu bằng chứng mật mã chứng minh các tệp nhật ký AWS CloudTrail lưu trữ trong một Amazon S3 archive bucket trong 12 tháng qua chưa bị sửa đổi, xóa hoặc giả mạo sau khi AWS phân phối chúng. Tính năng CloudTrail Log File Validation đã được bật khi tạo trail. Kỹ sư bảo mật nên xác minh tính toàn vẹn của các tệp nhật ký như thế nào?

**Đáp án đúng:** **B**

CloudTrail Log File Validation hoạt động bằng cơ chế SHA-256 hashing kết hợp RSA digital signatures trên các hourly digest files tạo thành chuỗi bất biến. Để kiểm chứng nhanh cho kiểm toán viên, dùng lệnh CLI `aws cloudtrail validate-logs --trail-arn <arn> --start-time <time>` (có thể xác minh cả file bị sửa đổi lẫn file bị xóa mất).

- **A:** S3 ETag không phải là cơ chế chứng minh toàn vẹn mật mã chống giả mạo (tamper-evident cryptographic proof) của CloudTrail, và không thể phát hiện việc một log file bị xóa hoàn toàn khỏi bucket.
- **B (Đúng):** Chính xác! CloudTrail Log File Validation tạo ra các digest file mỗi giờ chứa mã băm SHA-256 của từng log file và liên kết chuỗi (hash chain) với digest file trước đó, được ký số bằng private key của CloudTrail (RSA). Lệnh aws cloudtrail validate-logs xác minh cả chữ ký số của digest lẫn mã băm SHA-256 của toàn bộ log file.
- **C:** S3 Server Access Logs mang tính best-effort và không cung cấp bằng chứng mật mã (hash chain & chữ ký số) xác thực từng file log CloudTrail như Log File Validation.
- **D:** KMS dùng để mã hóa bảo mật nội dung (confidentiality) bằng symmetric key, không phải cơ chế chữ ký số digest file của CloudTrail Log File Validation.

</details>

### Câu 2 `hard`

A security team wants to detect two specific threats in near real time using AWS CloudTrail: (1) an unusual sudden spike in kms:Decrypt or iam:CreateAccessKey API calls compared to historical baselines, and (2) every individual s3:GetObject and s3:DeleteObject call targeting a specific PCI-regulated S3 bucket without paying to log data events for hundreds of other non-sensitive S3 buckets. Which CloudTrail configuration meets BOTH requirements most cost-effectively?

- **A.** Enable CloudTrail Insights for API anomalies and Advanced Event Selectors to log S3 Data Events for the PCI bucket ARN.
- **B.** Enable CloudTrail Management Events only, because Management Events automatically include S3 object-level GetObject calls and baseline anomaly detection.
- **C.** Enable CloudTrail Data Events for all S3 buckets in the account and write a custom Amazon SageMaker model to detect spikes in iam:CreateAccessKey.
- **D.** Use CloudTrail Event History in the AWS Management Console to set up automated anomaly alerts for s3:GetObject calls.

<details><summary>Xem đáp án, Dịch nghĩa & Giải thích chi tiết</summary>

> **Ý nghĩa câu hỏi:** Một nhóm bảo mật muốn phát hiện hai mối đe dọa cụ thể theo thời gian gần thực bằng AWS CloudTrail: (1) một đợt tăng đột biến bất thường trong các lệnh gọi API kms:Decrypt hoặc iam:CreateAccessKey so với đường cơ sở lịch sử, và (2) mọi lệnh gọi s3:GetObject và s3:DeleteObject riêng lẻ nhắm vào một S3 bucket tuân thủ PCI cụ thể mà không phải trả phí ghi log data event cho hàng trăm S3 bucket không nhạy cảm khác. Cấu hình CloudTrail nào đáp ứng CẢ HAI yêu cầu một cách tiết kiệm chi phí nhất?

**Đáp án đúng:** **A**

Nhớ rõ 3 loại sự kiện của CloudTrail: (1) **Management Events** (control plane), (2) **Data Events** (data plane như S3 object-level, Lambda invoke, DynamoDB items — luôn dùng **Advanced Event Selectors** để lọc chính xác tài nguyên nhằm tối ưu chi phí), và (3) **CloudTrail Insights** (tự động phát hiện đột biến API call rate & API error rate).

- **A (Đúng):** Chính xác! CloudTrail Insights tự động phân tích đường cơ sở lịch sử để phát hiện đột biến bất thường về tần suất gọi API (API call rate) hoặc tỷ lệ lỗi (API error rate). Advanced Event Selectors cho phép lọc chính xác S3 Data Events theo đúng ARN của bucket chứa dữ liệu PCI để tránh tốn chi phí log cho hàng trăm bucket khác.
- **B:** CloudTrail Management Events chỉ ghi nhận các thao tác control plane (như CreateBucket, PutBucketPolicy), KHÔNG ghi nhận object-level S3 Data Events (GetObject/DeleteObject) và không có sẵn anomaly detection nếu không bật CloudTrail Insights.
- **C:** Bật Data Events cho tất cả hàng trăm S3 bucket gây lãng phí chi phí cực lớn, và tự xây SageMaker model thay cho CloudTrail Insights gây tốn kém và phức tạp không cần thiết.
- **D:** CloudTrail Event History chỉ lưu Management Events trong 90 ngày, không chứa S3 Data Events và không hỗ trợ cảnh báo bất thường tự động.

</details>

### Câu 3 `hard`

A financial services company must prove to external auditors that AWS CloudTrail log files stored in an archive Amazon S3 bucket have not been modified, deleted, or tampered with since CloudTrail delivered them. The security team has already enabled CloudTrail log file validation on the organization trail. How should the team cryptographically verify the integrity of all log files delivered during a specific date range?

- **A.** Run `aws cloudtrail validate-logs` with the trail ARN and time range to verify SHA-256 hashes and RSA digest signatures.
- **B.** Query the S3 bucket's server access logs in Amazon Athena to confirm that no PutObject or DeleteObject API calls occurred.
- **C.** Compare the S3 ETag values of the CloudTrail log objects against the CloudWatch Logs metric counts for the same period.
- **D.** Enable Amazon Macie on the archive bucket to validate the SHA-256 checksums of all JSON log files.

<details><summary>Xem đáp án, Dịch nghĩa & Giải thích chi tiết</summary>

> **Ý nghĩa câu hỏi:** Một công ty dịch vụ tài chính phải chứng minh với kiểm toán viên bên ngoài rằng các tệp nhật ký AWS CloudTrail lưu trữ trong một Amazon S3 bucket lưu trữ chưa bị sửa đổi, xóa hoặc giả mạo kể từ khi CloudTrail phân phối chúng. Nhóm bảo mật đã bật xác thực tệp nhật ký CloudTrail trên organization trail. Nhóm nên xác minh bằng mật mã tính toàn vẹn của tất cả các tệp nhật ký được phân phối trong một khoảng ngày cụ thể như thế nào?

**Đáp án đúng:** **A**

**CloudTrail Log File Validation** tạo các **digest file** hàng giờ sử dụng SHA-256 hashing và chữ ký số RSA, liên kết với digest của giờ trước đó. Để xác minh tính toàn vẹn (chưa bị sửa, xóa hoặc chèn file giả), sử dụng lệnh CLI `aws cloudtrail validate-logs`.

- **A (Đúng):** Chính xác! Khi bật Log File Validation, CloudTrail tạo ra các digest file mỗi giờ chứa mã băm SHA-256 của các file log và chữ ký số RSA (liên kết chuỗi hash với digest trước đó). Lệnh `aws cloudtrail validate-logs` tự động tải digest và xác minh tính toàn vẹn mật mã của toàn bộ chuỗi log.
- **B:** Kiểm tra S3 access logs không cung cấp bằng chứng mật mã (cryptographic proof) rằng nội dung tệp log không bị sửa đổi hay xóa ngầm; ngoài ra access logs có tính chất best-effort.
- **C:** S3 ETag không phải là cơ chế xác thực chữ ký số chuỗi hash của CloudTrail và không thể chứng minh file log không bị thay thế hoặc xóa bỏ.
- **D:** Amazon Macie dùng để phát hiện dữ liệu nhạy cảm (PII), không có chức năng xác minh tính toàn vẹn digest/chữ ký số của CloudTrail.

</details>

### Câu 4 `hard`

A security team wants to automatically detect unusual spikes in IAM API error rates (such as AccessDenied errors caused by an attacker enumerating permissions) and anomalous increases in write API call volume across their AWS account, then receive near-real-time notifications in Slack via Amazon SNS. Which TWO configurations should the team implement? (Choose TWO.)

*(Chọn 2 đáp án)*

- **A.** Enable AWS CloudTrail S3 data events across all buckets to capture IAM AccessDenied API errors.
- **B.** Configure AWS Config managed rules to evaluate IAM API error spikes every 24 hours across the account.
- **C.** Enable AWS CloudTrail Insights on the trail for both API call rate and API error rate insight types.
- **D.** Enable VPC Flow Logs on the management VPC to capture and filter IAM API AccessDenied error codes.
- **E.** Create an EventBridge rule matching CloudTrail Insight events and route them to an Amazon SNS topic.

<details><summary>Xem đáp án, Dịch nghĩa & Giải thích chi tiết</summary>

> **Ý nghĩa câu hỏi:** Một nhóm bảo mật muốn tự động phát hiện các đợt tăng đột biến bất thường về tỷ lệ lỗi IAM API (như lỗi AccessDenied do kẻ tấn công liệt kê quyền) và sự gia tăng bất thường về khối lượng lệnh gọi write API trên tài khoản AWS của họ, sau đó nhận thông báo theo thời gian gần thực trên Slack thông qua Amazon SNS. Nhóm nên triển khai HAI cấu hình nào? (Chọn HAI đáp án.)

**Đáp án đúng:** **C, E**

**AWS CloudTrail Insights** hỗ trợ 2 loại phát hiện bất thường dựa trên baseline hành vi: **API call rate** (đột biến gọi API ghi) và **API error rate** (đột biến mã lỗi như AccessDenied). Kết hợp với **Amazon EventBridge** và **SNS** giúp gửi cảnh báo tự động ngay khi phát hiện bất thường.

- **A:** S3 data events chỉ ghi nhận hoạt động mức object trên S3 (GetObject, PutObject), không liên quan đến việc phát hiện bất thường tỷ lệ lỗi API IAM.
- **B:** AWS Config theo dõi thay đổi cấu hình tài nguyên (configuration snapshots/compliance), không phân tích lưu lượng hay tỷ lệ lỗi lời gọi API theo thời gian thực.
- **C (Đúng):** Chính xác! CloudTrail Insights liên tục phân tích các sự kiện quản trị CloudTrail để phát hiện bất thường về tốc độ gọi API ghi (`ApiCallRateInsight`) và tỷ lệ lỗi API (`ApiErrorRateInsight`, ví dụ đột biến AccessDenied khi kẻ tấn công dò quyền).
- **D:** VPC Flow Logs chỉ ghi metadata tầng IP/TCP/UDP, không đọc được nội dung HTTPS hay mã lỗi API IAM ở tầng ứng dụng.
- **E (Đúng):** Chính xác! Khi CloudTrail Insights phát hiện bất thường, nó phát sinh sự kiện CloudTrail Insights lên EventBridge; tạo rule EventBridge bắt các sự kiện này và gửi tới SNS topic giúp cảnh báo gần thời gian thực tới Slack.

</details>

### Câu 5 `hard`

An organization centralizes AWS CloudTrail logs from all member accounts into a single Amazon S3 bucket in the Log Archive account. Auditors require strict controls ensuring that even a compromised administrator in the Log Archive account or a member account cannot delete archived log objects for 5 years and cannot disable or alter the organization trail. Which TWO controls should the security team implement? (Choose TWO.)

*(Chọn 2 đáp án)*

- **A.** Enable S3 Object Lock in Governance mode so that administrators with s3:BypassGovernanceRetention can still clean up old logs when needed.
- **B.** Attach a Service Control Policy (SCP) to the management account denying cloudtrail:StopLogging.
- **C.** Enable S3 Object Lock in Compliance mode with a 5-year retention period on the Log Archive S3 bucket.
- **D.** Use S3 Bucket ACLs set to Private so that IAM administrators in the Log Archive account cannot delete objects.
- **E.** Configure an AWS Organizations Trail from the management/delegated admin account so member admins cannot stop it.

<details><summary>Xem đáp án, Dịch nghĩa & Giải thích chi tiết</summary>

> **Ý nghĩa câu hỏi:** Một tổ chức tập trung nhật ký AWS CloudTrail từ tất cả các tài khoản thành viên vào một Amazon S3 bucket duy nhất trong tài khoản Log Archive. Kiểm toán viên yêu cầu các biện pháp kiểm soát nghiêm ngặt đảm bảo rằng ngay cả một quản trị viên bị xâm phạm trong tài khoản Log Archive hoặc tài khoản thành viên cũng không thể xóa các đối tượng nhật ký đã lưu trữ trong 5 năm và không thể tắt hoặc sửa đổi organization trail. Nhóm bảo mật nên triển khai HAI biện pháp kiểm soát nào? (Chọn HAI đáp án.)

**Đáp án đúng:** **C, E**

Để bảo vệ tuyệt đối nhật ký CloudTrail đa tài khoản: (1) Dùng **Organization Trail** để member accounts không thể tắt/sửa trail; (2) Bật **S3 Object Lock ở chế độ Compliance mode** (không phải Governance mode) để ngay cả root user của tài khoản Log Archive cũng không thể xóa log trước hạn 5 năm.

- **A:** Governance mode cho phép admin có quyền `s3:BypassGovernanceRetention` xóa sớm hoặc bỏ qua thời hạn lưu giữ, không đáp ứng yêu cầu ngay cả admin bị chiếm quyền cũng không thể xóa log trong 5 năm.
- **B:** SCP không bao giờ có tác dụng đối với tài khoản Management Account của AWS Organizations.
- **C (Đúng):** Chính xác! S3 Object Lock ở chế độ **Compliance mode** đảm bảo không một ai—kể cả tài khoản root của Log Archive account—có thể xóa hoặc ghi đè object hay rút ngắn thời gian lưu giữ trong suốt 5 năm.
- **D:** S3 Bucket ACL chỉ kiểm soát truy cập ở mức cơ bản/cross-account và không ngăn được IAM administrator trong cùng tài khoản Log Archive xóa object.
- **E (Đúng):** Chính xác! Với Organization Trail, quản trị viên trong các member account chỉ có quyền xem (read-only) đối với trail của tổ chức và hoàn toàn không thể dừng (StopLogging), xóa hoặc chỉnh sửa cấu hình trail.

</details>

### Câu 6 `hard`

A company hosts a high-volume Amazon S3 data lake processing 50 million s3:GetObject requests daily. Enabling standard CloudTrail S3 data events on the bucket generated unexpectedly high CloudTrail costs. The security team only needs to log destructive or configuration-changing data events—specifically s3:DeleteObject and s3:PutObjectAcl—on two sensitive prefixes while completely excluding s3:GetObject events. How should the team configure CloudTrail?

- **A.** Use Basic Event Selectors with Read/Write type set to All and filter out GetObject events later using an S3 Lifecycle rule.
- **B.** Enable S3 Server Access Logging instead of CloudTrail because Server Access Logs filter by eventName before S3 delivery.
- **C.** Disable CloudTrail data events and rely on CloudTrail management events to capture s3:DeleteObject and s3:PutObjectAcl calls.
- **D.** Configure CloudTrail Advanced Event Selectors for AWS::S3::Object filtered by eventName and the two sensitive bucket prefixes.

<details><summary>Xem đáp án, Dịch nghĩa & Giải thích chi tiết</summary>

> **Ý nghĩa câu hỏi:** Một công ty lưu trữ một Amazon S3 data lake lưu lượng cao xử lý 50 triệu request s3:GetObject mỗi ngày. Việc bật CloudTrail S3 data events tiêu chuẩn trên bucket tạo ra chi phí CloudTrail cao bất ngờ. Nhóm bảo mật chỉ cần ghi nhật ký các sự kiện dữ liệu mang tính phá hủy hoặc thay đổi cấu hình—cụ thể là s3:DeleteObject và s3:PutObjectAcl—trên hai tiền tố nhạy cảm trong khi loại trừ hoàn toàn các sự kiện s3:GetObject. Nhóm nên cấu hình CloudTrail như thế nào?

**Đáp án đúng:** **D**

**CloudTrail Advanced Event Selectors** là giải pháp chuẩn để tối ưu chi phí cho **Data Events** (S3, Lambda, DynamoDB) bằng cách lọc chính xác theo `eventName`, `resources.ARN`, `readOnly`, và `eventCategory` ngay tại nguồn trước khi tính phí.

- **A:** Basic Event Selectors với Read/Write = All vẫn tính phí CloudTrail cho toàn bộ 50 triệu lệnh `GetObject` mỗi ngày; S3 Lifecycle chỉ xóa file sau khi đã phát sinh chi phí ghi log CloudTrail.
- **B:** S3 Server Access Logging không cho phép lọc trước theo `eventName` và có tính chất best-effort, không thay thế được độ chính xác kiểm toán của CloudTrail Advanced Event Selectors.
- **C:** `s3:DeleteObject` là thao tác mức object (**data event**), hoàn toàn không được ghi trong CloudTrail management events.
- **D (Đúng):** Chính xác! **CloudTrail Advanced Event Selectors** cho phép lọc chi tiết data events theo `eventName` (chỉ ghi `DeleteObject`, `PutObjectAcl`), loại trừ `GetObject`, và lọc chính xác theo `resources.ARN` (bucket/prefix), giúp giảm mạnh chi phí CloudTrail data events.

</details>

### Câu 7 `hard`

A fintech company enables AWS WAF logging to an Amazon S3 bucket for forensic analysis. Compliance auditors discover that the WAF logs currently contain sensitive bearer tokens in the Authorization HTTP header and session tokens in the Cookie header, violating PCI DSS logging rules. Additionally, the team wants to reduce log storage costs by logging ONLY requests that are BLOCKED or COUNTED by WAF. How should the team configure AWS WAF logging?

- **A.** Write an AWS Lambda function triggered by S3 PutObject to download every WAF log file, scrub the Authorization header, and overwrite the S3 object.
- **B.** Enable AWS WAF logging field redaction for Authorization and Cookie headers, and add a Drop filter keeping only BLOCK or COUNT actions.
- **C.** Enable Amazon Macie automated discovery on the WAF log bucket to automatically redact Authorization headers in real time.
- **D.** Disable AWS WAF logging completely and inspect blocked HTTP requests and headers using VPC Flow Logs instead.

<details><summary>Xem đáp án, Dịch nghĩa & Giải thích chi tiết</summary>

> **Ý nghĩa câu hỏi:** Một công ty fintech bật ghi nhật ký AWS WAF tới một Amazon S3 bucket để phân tích điều tra số. Kiểm toán viên tuân thủ phát hiện rằng nhật ký WAF hiện đang chứa các bearer token nhạy cảm trong header HTTP Authorization và session token trong header Cookie, vi phạm quy tắc ghi nhật ký PCI DSS. Ngoài ra, nhóm muốn giảm chi phí lưu trữ nhật ký bằng cách CHỈ ghi nhật ký các request bị BLOCKED hoặc COUNTED bởi WAF. Nhóm nên cấu hình ghi nhật ký AWS WAF như thế nào?

**Đáp án đúng:** **B**

Trong **AWS WAF Logging**, hãy luôn tận dụng 2 tính năng tích hợp sẵn: **Field Redaction** (loại bỏ `Authorization`, `Cookie`, query string nhạy cảm trước khi xuất log) và **Logging Filters** (chỉ ghi lại `BLOCK`/`COUNT` thay vì toàn bộ `ALLOW` để tiết kiệm chi phí lưu trữ).

- **A:** Dữ liệu nhạy cảm vẫn kịp ghi xuống S3 trước khi Lambda chạy (vi phạm tuân thủ), đồng thời tốn chi phí và công sức vận hành không cần thiết khi WAF đã có sẵn tính năng field redaction.
- **B (Đúng):** Chính xác! AWS WAF Logging hỗ trợ sẵn **Redacted fields** (ẩn/xóa các trường nhạy cảm như header `Authorization`, `Cookie`, query string, URI trước khi ghi log) và **Logging filters** (đặt default behavior = Drop và giữ lại các request có action = BLOCK hoặc COUNT) ngay tại dịch vụ WAF mà không cần xử lý hậu kỳ.
- **C:** Amazon Macie chỉ phát hiện và báo cáo dữ liệu nhạy cảm, không có tính năng chỉnh sửa hay che giấu (redact) nội dung file log.
- **D:** VPC Flow Logs không ghi nhận các quyết định chặn/đếm ở tầng ứng dụng của AWS WAF.

</details>

### Câu 8 `hard`

A company replaces all SSH bastion hosts with AWS Systems Manager Session Manager so administrators can access private EC2 instances without opening port 22. Security auditors require that every command and terminal output from every Session Manager session be encrypted at rest and logged centrally, and that administrators cannot bypass or disable session logging. Which TWO configurations should the security team implement? (Choose TWO.)

*(Chọn 2 đáp án)*

- **A.** Enable CloudTrail data events for AWS Systems Manager to record every bash command typed inside a Session Manager terminal session.
- **B.** Open inbound TCP port 22 on EC2 security groups from the Systems Manager service IP range so Session Manager can capture SSH logs.
- **C.** Configure Session Manager preferences to stream KMS-encrypted session logs to CloudWatch Logs or S3, and enable KMS encryption in transit.
- **D.** Store session logs exclusively in the local /var/log directory on each EC2 instance so security administrators can audit them directly.
- **E.** Deny ssm:UpdateDocument on SSM-SessionManagerRunShell for admins, and grant the EC2 instance profile permissions to write logs and use KMS.

<details><summary>Xem đáp án, Dịch nghĩa & Giải thích chi tiết</summary>

> **Ý nghĩa câu hỏi:** Một công ty thay thế toàn bộ SSH bastion host bằng AWS Systems Manager Session Manager để quản trị viên có thể truy cập các EC2 instance riêng tư mà không cần mở port 22. Kiểm toán viên bảo mật yêu cầu mọi lệnh và đầu ra terminal từ mọi phiên Session Manager phải được mã hóa khi lưu trữ (at rest) và ghi nhật ký tập trung, đồng thời quản trị viên không thể bỏ qua hoặc tắt việc ghi nhật ký phiên. Nhóm bảo mật nên triển khai HAI cấu hình nào? (Chọn HAI đáp án.)

**Đáp án đúng:** **C, E**

Kiến trúc kiểm toán chuẩn cho **SSM Session Manager**: (1) Bật **Session Manager Preferences** xuất log mã hóa KMS sang **CloudWatch Logs / S3** (CloudTrail chỉ ghi `StartSession`, không ghi lệnh bên trong); (2) Chặn quyền `ssm:UpdateDocument` trên `SSM-SessionManagerRunShell` để chống tắt log và cấp quyền ghi log/KMS cho **EC2 instance profile**.

- **A:** CloudTrail chỉ ghi nhận lời gọi API `ssm:StartSession` / `ssm:TerminateSession`, KHÔNG ghi lại các câu lệnh bash hay output bên trong phiên terminal (chỉ Session Manager logging gửi sang CloudWatch Logs/S3 mới ghi nội dung phiên).
- **B:** Session Manager hoạt động qua kết nối outbound HTTPS (port 443) từ SSM Agent tới Systems Manager endpoints, hoàn toàn không dùng SSH hay mở inbound port 22.
- **C (Đúng):** Chính xác! Session Manager cho phép cấu hình Preferences để tự động ghi toàn bộ nhật ký phiên (lệnh và output) được mã hóa KMS về CloudWatch Logs (streaming) và/hoặc S3, đồng thời hỗ trợ mã hóa thêm dữ liệu phiên bằng KMS key riêng.
- **D:** Lưu log cục bộ trên EC2 vừa không tập trung, vừa dễ bị chính người dùng có quyền trên EC2 xóa hoặc chỉnh sửa.
- **E (Đúng):** Chính xác! Cấu hình Session Manager Preferences được lưu trong SSM document `SSM-SessionManagerRunShell`; chặn quyền sửa document này ngăn admin tắt logging, và EC2 instance profile cần có quyền ghi log (`logs:PutLogEvents`/`s3:PutObject`) cùng quyền `kms:GenerateDataKey` để đẩy log thành công.

### Câu 9 `hard`

A financial institution uses an AWS Organizations trail to deliver CloudTrail logs from all member accounts to a centralized S3 bucket in the Log Archive account. During a regulatory audit, the auditor demands cryptographic proof that none of the CloudTrail log files have been modified, deleted, or tampered with since delivery, and requires that not even the Log Archive account's root user can delete logs for 7 years. Which combination of controls satisfies these requirements?

- **A.** Enable CloudTrail log file integrity validation and S3 Object Lock in Compliance mode (7-year retention) on the bucket.
- **B.** Enable SSE-KMS encryption on the S3 bucket and configure S3 Object Lock in Governance mode with a 7-year retention period.
- **C.** Enable S3 Versioning, attach a bucket policy denying s3:DeleteObject to all principals, and enable CloudTrail Insights.
- **D.** Deliver CloudTrail logs to Amazon CloudWatch Logs with a 7-year retention policy and enable KMS encryption on the log group.

<details><summary>Xem đáp án, Dịch nghĩa & Giải thích chi tiết</summary>

> **Ý nghĩa câu hỏi:** Một tổ chức tài chính sử dụng AWS Organizations trail để phân phối nhật ký CloudTrail từ tất cả tài khoản thành viên tới một S3 bucket tập trung trong tài khoản Log Archive. Trong một đợt kiểm toán quy định, kiểm toán viên yêu cầu bằng chứng mật mã chứng minh không có tệp nhật ký CloudTrail nào bị sửa đổi, xóa hoặc giả mạo kể từ khi phân phối, và yêu cầu ngay cả root user của tài khoản Log Archive cũng không thể xóa nhật ký trong 7 năm. Sự kết hợp các biện pháp kiểm soát nào đáp ứng các yêu cầu này?

**Đáp án đúng:** **A**

Hai từ khóa vàng trong đề thi SCS-C02: 'cryptographic proof of no tampering' → CloudTrail Log File Integrity Validation (SHA-256 + RSA digest); 'not even root user can delete' → S3 Object Lock Compliance Mode.

- **A (Đúng):** Chính xác! CloudTrail Log File Integrity Validation tạo digest SHA-256 ký số RSA mỗi giờ để chứng minh tính toàn vẹn bằng mật mã (kiểm tra qua aws cloudtrail validate-logs), còn S3 Object Lock ở Compliance Mode đảm bảo kể cả Root User cũng không thể xóa log trong 7 năm.
- **B:** SSE-KMS chỉ mã hóa bảo mật (confidentiality), không cung cấp bằng chứng chống sửa đổi/xóa file như Log File Validation; ngoài ra Governance Mode vẫn cho phép người có quyền s3:BypassGovernanceRetention xóa log.
- **C:** Root user của Log Archive account vẫn có thể sửa hoặc xóa S3 Bucket Policy để gỡ lệnh Deny, do đó không đáp ứng yêu cầu chặn cả Root user; CloudTrail Insights cũng không dùng để xác thực toàn vẹn file log.
- **D:** CloudWatch Logs không cung cấp cơ chế digest ký số xác thực tính toàn vẹn như CloudTrail Log File Integrity Validation và không có cơ chế WORM chống xóa bởi Root user như S3 Object Lock Compliance Mode.

</details>

### Câu 10 `medium`

A security operations team must be alerted within minutes whenever more than 5 unauthorized API calls (AccessDenied or UnauthorizedOperation) occur within a 5-minute window in a production AWS account. What is the MOST operationally efficient solution?

- **A.** Create an Amazon EventBridge rule matching CloudTrail events with errorCode AccessDenied and send them directly to an Amazon SNS topic.
- **B.** Schedule an Amazon Athena query via EventBridge every 5 minutes to scan the CloudTrail S3 bucket and invoke a Lambda function to notify SNS.
- **C.** Send CloudTrail logs to CloudWatch Logs, create a Metric Filter for AccessDenied/UnauthorizedOperation, and trigger a >5/5m Alarm to SNS.
- **D.** Enable AWS Config managed rules to monitor IAM AccessDenied errors and trigger an SSM Automation notification.

<details><summary>Xem đáp án, Dịch nghĩa & Giải thích chi tiết</summary>

> **Ý nghĩa câu hỏi:** Một nhóm vận hành bảo mật phải được cảnh báo trong vòng vài phút bất cứ khi nào có hơn 5 lệnh gọi API trái phép (AccessDenied hoặc UnauthorizedOperation) xảy ra trong khoảng thời gian 5 phút trong một tài khoản AWS production. Giải pháp hiệu quả về mặt vận hành NHẤT là gì?

**Đáp án đúng:** **C**

Phân biệt rõ trong Domain 2: Cảnh báo cho 1 sự kiện đơn lẻ (ví dụ Root Login) → EventBridge Rule; Cảnh báo theo ngưỡng đếm trong khoảng thời gian (ví dụ > 5 lỗi AccessDenied trong 5 phút) → CloudTrail + CloudWatch Logs Metric Filter + CloudWatch Alarm.

- **A:** EventBridge xử lý từng sự kiện riêng lẻ (stateless), nên nó sẽ gửi thông báo ngay từ lần lỗi đầu tiên thay vì đếm ngưỡng > 5 lần trong 5 phút.
- **B:** CloudTrail ghi log vào S3 thường có độ trễ 5–15 phút, đồng thời việc chạy Athena định kỳ kém hiệu quả và tốn công vận hành hơn nhiều so với CloudWatch Metric Filter.
- **C (Đúng):** Chính xác! Khi yêu cầu cảnh báo theo NGƯỠNG TẦN SUẤT trong cửa sổ thời gian (> 5 lần trong 5 phút), mô hình chuẩn là CloudTrail → CloudWatch Logs → Metric Filter → CloudWatch Alarm → SNS.
- **D:** AWS Config theo dõi thay đổi cấu hình tài nguyên, không theo dõi các lỗi gọi API (AccessDenied) theo thời gian thực.

</details>
